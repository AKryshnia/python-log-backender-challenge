## РЕШЕНИЕ ЗАДАЧИ

Идея для решения задачи: вместо прямой записи события в ClickHouse при выполнении бизнес-логики событие будет сохраняться в локальную (PostgreSQL) таблицу outbox в рамках той же транзакции. 
Затем отдельный фоновой процесс (Celery-задача) периодически будет считывать накопленные события, пакетировать их и отправлять в ClickHouse.
Был реализован механизм транзакционного outbox для логирования событий, который позволяет:
- Сохранять события в PostgreSQL для обеспечения транзакционности.
- Пакетно отправлять события в ClickHouse через Celery-задачу, что уменьшает количество мелких вставок и защищает систему от потерь при сетевых ошибках.
- Интегрировать структурированное логирование (с помощью structlog).

Основные компоненты архитектурного решения:

- Django-приложение: Обрабатывает бизнес-логику (например, создание пользователя) и инициирует логирование событий.
- Транзакционный outbox: Модель EventOutbox в PostgreSQL сохраняет события, прежде чем они будут отправлены в ClickHouse.
- Celery-задача: send_events_to_clickhouse периодически извлекает события из outbox, пакетно отправляет их в ClickHouse, а затем удаляет успешно обработанные записи.
- ClickHouse: Используется как база данных для аналитики и аудита, куда события отправляются пакетной вставкой.
- Используется structlog для логирования.

Использование приложения

Логирование событий:
- При выполнении бизнес-операций (например, создание пользователя через use case CreateUser) вызывается метод EventService.log_event. События сохраняются в таблицу event_outbox в PostgreSQL.
Передача логов в ClickHouse:
- Celery-задача send_events_to_clickhouse (настроенная через Celery Beat и/или запускаемая вручную) извлекает события из event_outbox, пакетно отправляет их в ClickHouse и удаляет обработанные записи.
- Таким образом, лог-система работает асинхронно и защищена от проблем синхронной записи.
Тесты включают проверку:
- Успешного создания пользователя.
- Корректности логирования события в event_outbox и его отправки в ClickHouse (тест test_event_log_entry_published).
- Обеспечения уникальности email.

Для просмотра логов приложения: 
docker compose logs -f app
